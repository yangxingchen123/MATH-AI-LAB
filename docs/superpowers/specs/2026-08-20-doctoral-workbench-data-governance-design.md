# MATH-AI-LAB 数据治理与学术诚信规范

**状态：** Candidate
**上位契约：** [博士级数学研究工作台总架构](2026-08-20-doctoral-research-workbench-design.md)
**适用范围：** 所有研究版本和 Sidecar

---

## 1. 目标

博士级工作台不仅要得到正确结果，还要合法、可负责地处理资料、数据、模型输出、作者贡献和正式发布。本规范定义数据分级、远程处理、Git/大文件、许可、保留、删除和 AI 贡献边界。

数据等级不清、许可不清或授权不清时，先阻断高风险动作，不通过默认上传来“试试看”。

---

## 2. 数据分级

| 等级 | 典型内容 | 默认处理 |
| --- | --- | --- |
| `PUBLIC` | 明确公开且许可允许处理的论文、开源数据、公开代码 | 可在获批本地或远程引擎处理，仍记录许可和来源 |
| `PERSONAL` | 个人笔记、未公开草稿、可识别个人信息、个人研究轨迹 | 数据最小化；优先本地；远程需明确服务许可和必要性 |
| `RESTRICTED` | 保密数据、受合同限制资料、未公开合作者材料、敏感人类数据 | 默认仅在明确批准的本地/隔离环境；无明确授权不得发送远程 |

混合数据按最高等级处理。去标识化只有在再识别风险经过审查后才允许降级；删掉姓名不自动等于匿名。

每个 Source、Derived Package、run、index 和外部任务记录数据等级及判定依据。

---

## 3. 本地与远程处理矩阵

| 数据等级 | 本地开源引擎 | 已批准远程服务 | 未知/临时远程服务 |
| --- | --- | --- | --- |
| `PUBLIC` | 允许 | 允许，记录服务和版本 | 禁止正式任务，先审查条款 |
| `PERSONAL` | 优先允许 | 仅最小必要数据、明确目的和保留策略 | 禁止 |
| `RESTRICTED` | 仅在获批隔离环境 | 默认禁止；必须有项目级明确授权与合同依据 | 禁止 |

远程请求不得包含未使用字段、无关页面、完整资料库或 secrets。Provider 的训练、保留、地域、子处理者和删除政策必须在使用前记录；政策变化触发重新审查。

---

## 4. Git 与大文件政策

### 4.1 应跟踪

- 源代码、测试、配置和锁文件；
- 小型、许可明确的固定 fixture；
- manifest、provenance、review 和决策记录；
- 审核后的 Markdown、Lean 和 LaTeX source；
- 小型 canonical 结果和正式图表 source；
- 外部数据/文档的 URI、hash、版本和许可说明。

### 4.2 默认忽略

- 未经许可分发的原始论文 PDF；
- MinerU 模型、OCR 缓存和解析临时目录；
- Python/solver/model cache；
- 向量数据库和可重建索引；
- secrets、token、credential 和本机配置；
- 大型瞬态 run 输出、checkpoint 和日志；
- 含 Personal/Restricted 内容的派生缓存；
- 构建中间文件。

### 4.3 外部存储并提交引用

- 大型数据集；
- 模型权重；
- 受版权或合同限制的 Source；
- 大型仿真输出；
- 可重建但需长期保留的 binary artifact。

外部引用至少包含 URI/对象键、SHA-256、大小、版本、所有者、数据等级、许可、获取/生成方法和可用性要求。

Git LFS 不是默认答案。只有仓库协作、配额、许可和长期可访问性均审查通过时才显式启用；启用也不能绕过数据等级和再分发限制。

---

## 5. Secrets 与身份凭据

- 通过环境变量、操作系统 keychain 或批准的 secret store 提供；
- 不进入 Git、manifest、日志、prompt、截图或错误消息；
- Adapter 只读取完成任务所需的最小 scope；
- 日志在写盘前执行 secret redaction；
- 泄漏怀疑触发立即停用、轮换、影响检查和事件记录；
- 不要求用户在研究 Markdown 中粘贴凭据。

health-check 只报告 credential 是否可用，不显示其值。

---

## 6. 许可与版权

每个第三方 Source、数据集、模型、软件和素材记录：

- 标题/名称、作者/权利人；
- 来源 URL 或稳定标识；
- 精确版本/访问日期；
- 许可证或使用条款；
- 允许的处理、修改、再分发和发表范围；
- 归属要求；
- 未解决限制和项目决定。

公开可访问不等于允许再分发。仓库可以保存来源引用和 hash，而不提交受版权限制原文。短引用遵守合理范围；精选稿以自主分析和精确定位为主，不复制整章或整篇资料。

MinerU、求解器、字体、模型权重和图片素材分别检查许可，不能只记录顶层软件许可证。

## 7. 学术诚信

### 7.1 内容身份

研究成果必须明确区分：

- 原始来源的直接短引文；
- 对来源的忠实转述；
- 作者/AI 的推断；
- 程序或求解器输出；
- Lean 形式化结果；
- 已人工审查的最终表述。

不得捏造来源、DOI、数据、实验、证明、作者贡献或审稿结果。不能验证的历史归属或引用标记为待查证，不能凭记忆填充。

### 7.2 AI 贡献记录

每个正式研究成果维护 AI Contribution Log，至少记录：

- 使用的系统/模型和可识别版本；
- 使用日期与任务类型；
- AI 参与的检索、摘要、代码、分析、制图、形式化或编辑范围；
- 人工如何核查；
- 哪些候选被拒绝或实质修订；
- 是否向外部服务发送数据及其等级；
- 期刊、机构或资助方要求的披露文本。

不要求保存可能含敏感数据的全部原始 prompt；可以保存经过脱敏的任务摘要、策略 hash 和关键决策。

### 7.3 作者责任

- AI 不是作者，也不承担责任；
- 人类作者对数学正确性、数据、引用、许可、复现和披露负责；
- 署名只基于真实学术贡献并符合目标 venue 政策；
- 合作者材料和贡献不得未经同意上传、改写或发布；
- AI 生成代码和图像仍须执行许可、准确性和来源审查。

---

## 8. 人类数据、同意与伦理

涉及人类参与者、可识别个人数据、医疗/教育/行为数据或受监管数据时：

- 在采集或处理前确认伦理审批、知情同意和允许用途；
- 只处理研究目标需要的最小字段；
- 记录访问控制和审计日志；
- 训练、embedding、RAG 和远程模型使用必须在批准范围内；
- 输出执行隐私和再识别风险检查；
- 不能由本规范替代 IRB、伦理委员会、合同或法律审查。

没有明确批准时，系统应阻断相关 Sidecar 调用，而不是仅给警告后继续。

## 9. 保留、删除与重建

| 内容 | 保留原则 |
| --- | --- |
| Source 身份、hash、许可和决策 | 按项目与法律要求长期保留 |
| Reviewed Evidence、正式 run、Figure、Lean build | 随成果和复现要求保留 |
| 失败 run 与负结果 | 保留研究价值和审计所需版本 |
| 可重建缓存和索引 | 按成本与数据等级定期清理 |
| secrets | 不写盘；泄漏立即轮换 |
| Personal/Restricted 临时副本 | 最短必要期限，任务结束按政策删除 |

删除时记录目标、理由、授权、时间、是否可恢复和受影响 provenance。Source 被合法删除后，可保留不含原文的 hash/引用记录，前提是合同和隐私政策允许。

Generated index 必须可由允许保留的 Source/manifest 重建；不可重建的内容不得伪装为普通缓存。

---

## 10. 环境与许可矩阵

每个外部引擎维护可审计矩阵：

| 字段 | 要求 |
| --- | --- |
| Capability | 提供的稳定能力 |
| Engine | 名称与精确版本 |
| OS / Runtime | 支持平台与 Python/Lean/Node 等版本 |
| Hardware | CPU、内存、磁盘、GPU |
| License | 软件、模型、字体、数据许可 |
| Data ceiling | 允许处理的最高数据等级 |
| Remote behavior | 发送字段、地域、保留、训练政策 |
| Fallback | 替代引擎或显式降级 |
| Health Evidence | 最近 fixture 和验证日期 |
| Supersession | 替代引擎及迁移期 |

矩阵事实变化时，相关能力重新 health-check；不能只在首次安装时检查。

---

## 11. 事件响应

以下事件必须阻断相关发布或远程任务：

- secret 泄漏或疑似泄漏；
- Restricted 数据越权发送；
- 未知许可的素材进入正式成果；
- 引用或数据伪造；
- Source 被撤稿、更正或合法删除并影响结论；
- AI 输出被发现包含敏感复现内容或不当归属。

响应流程：停止影响面 → 保存最小安全证据 → 撤销/轮换权限 → 定位受影响 artifact → 标记 stale/撤回 → 修复与复核 → 形成 append-only 事件和决策记录。

---

## 12. 治理 Gate

每个版本发布候选至少满足：

- Source、Derived Package、正式 run 和索引的数据等级覆盖率 `100%`；
- Restricted 数据未授权远程发送次数 `0`；
- secrets 出现在 Git、manifest、日志和正式文档的次数 `0`；
- 外部引擎/数据/模型/字体的许可记录完整率 `100%`；
- 正式成果核心内容的 AI Contribution Log 覆盖率 `100%`；
- 引用/转述/推断误标的已知 fixture 检出率 `100%`；
- 未记录来源的第三方图像或数据进入发布候选次数 `0`；
- 可重建索引的重建测试成功率 `100%`；
- 删除操作的授权、目标和影响记录完整率 `100%`。

治理 Gate 失败不能通过“仅内部使用”自动豁免；应阻断受影响能力并保留无风险 Core 路径。
