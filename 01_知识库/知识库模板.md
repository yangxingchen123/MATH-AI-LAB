本模板依据 Knowledge Schema v1。`K0000` 仅为模板占位编号，创建真实 Knowledge 时必须替换为新的合法 K ID。

---

## Metadata 使用说明

复制本文件新建 Knowledge 时，优先修改 YAML 中的：`id`、`title`、`aliases`、`created`、`updated`，再写正文。

### id

* 真实 Knowledge：`K` + 4 位数字，如 `K0001`（格式 `^K\d{4}$`）。
* **`K0000` 仅为模板 / Schema 示例编号，禁止真实分配。**
* 真实编号从 `0001` 起，正式分配后原则上不复用、不改号。

### type

固定：

```yaml
type: knowledge
```

### status

允许：`draft` / `reviewed` / `archived`。新建默认 `draft`。

### domain

* `draft`：可省略（本模板故意不预填，避免留下假领域）。
* `reviewed`：必须存在；类型为 string；`trim` 后非空。
* Schema v1 **不**强制受控词表。

非法：`domain:`（空键）、`domain: ""`。

### aliases

* `draft`：可省略；若写出须为数组。
* `reviewed`：必须存在为数组；无别名时写 `aliases: []`。

### prerequisites

只记录 **direct prerequisite**（理解本对象前真正需要的直接前置 Knowledge）。不要堆传递祖先。

语义：若 `prerequisites` 含某个真实 reviewed Knowledge ID，表示「理解本对象前需要该 ID」，不是反向依赖。

* target 必须是真实 Knowledge ID（非 `K0000`）。
* `reviewed` 时：字段必须存在（可为 `[]`）；每个非空 target 须存在、`type: knowledge`、`status: reviewed`。
* 全体 Knowledge 的 `prerequisites` 图必须为 **DAG（无环）**。
* 禁止自引用。

反向「谁引用了我」由未来索引生成；不要手写 `used_by` / `required_by` 等字段。

### related

强关联但不是 prerequisite。人工只维护一侧。

* `reviewed` 时字段必须存在（可为 `[]`）；非空 target 须存在、`type: knowledge`、`status: reviewed`。
* **允许成环**（与 prerequisites 不同）。
* 禁止自引用。

### created / updated

* 新建：二者都填实际创建日期 `YYYY-MM-DD`。
* 以后在数学正文实质变化、Metadata 关系变化、或 `status` 变化时更新 `updated`。
* 纯格式微调不必强制改 `updated`。

### 升级到 reviewed 前至少确认

* `aliases` 存在（数组）
* `domain` 非空 string
* `prerequisites` 存在（数组，可为 `[]`）
* `related` 存在（数组，可为 `[]`）
* 关系 target 合法
* 数学正文已经人工审核

### 不要加入的字段

不要写 Frozen Knowledge Schema v1 之外的字段，例如：`difficulty`、`mastery`、`tags`、`source_problems`、`used_in_problems`、`rag_id`、`embedding_id` 等。也不要在新条目中维护「来源研究」类 Problem 来源字段（等 Problem Schema 后再处理）。

### reviewed YAML 示意（不可直接当作真实对象）

以下仅为 Schema 示例，`K0000` 永远不能用于真实对象；`domain: 示例领域` 只是 documentation 占位，不是受控值。

```yaml
---
schema_version: 1

id: K0000
type: knowledge
title: 示例知识条目
aliases: []

status: reviewed
created: 2026-08-19
updated: 2026-08-19

domain: 示例领域

prerequisites: []
related: []
---
```

关系格式示意（不要放进真实 YAML Front Matter，除非已换成真实 reviewed ID）：

```yaml
prerequisites:
  - <真实的 reviewed Knowledge ID>
related: []
```

# 示例知识条目

（创建真实对象时，将一级标题改为正式 `title`。）

正文结构是**推荐学习组织**，不是 Schema 强制章节。可按概念 / 定义 / 定理 / 变换 / 专题等对象类型增删合并。

---

## 一、为什么需要这个知识

* 它解决什么问题？
* 为什么会想到它？
* 学它有什么用？

---

## 二、核心直觉

用自然语言、几何、图像或简单例子解释。可与「几何意义」合并。

---

## 三、正式定义

给出严谨数学定义。明确：对象、条件、符号、定义域。

---

## 四、等价刻画 / 判别方法

仅当该知识确实有常用等价刻画或判别时填写；否则删除本节或注明「暂无」。

---

## 五、典型例子

至少让读者看清定义长什么样。可含反例（若适合）。

---

## 六、重要性质

只放长期有价值的核心性质，不要堆手册。

---

## 七、推导 / 证明 / 原理

按对象需要选用；不要求每个 Knowledge 都有完整证明。

---

## 八、与其他知识的联系

用自然语言说明数学联系。结构化 `prerequisites` / `related` 只写在 YAML，不要在正文再维护一套正式 ID 关系表。

---

## 九、常见误区

整理学习与复习中易错点。

---

## 十、本节要点

少量结论，便于复习。

---

## （可选）参考资料

教材、论文、讲义等原始出处。非正式 Schema 字段。
