## Candidate Contract: Research Record Grammar

Authority for full legal/illegal examples: Spec §3 (`docs/superpowers/specs/2026-08-20-doctoral-workbench-research-workflow-design.md`). This plan restates the exact Candidate Contract implementers must code and test.

### Boundaries (sole split basis)

Every record uses **paired markers**. Parser **must** use BEGIN/END markers only. **Never** split on `##` headings. Nested `##` (or any Markdown heading) inside body **must not** truncate the record.

```text
<!-- MATH-AI-LAB:RESEARCH-RECORD type=ASSUMPTION ref=ASM-0001 BEGIN -->
...
<!-- MATH-AI-LAB:RESEARCH-RECORD type=ASSUMPTION ref=ASM-0001 END -->
```

| Rule | Requirement |
| --- | --- |
| Types | `ASSUMPTION`, `CLAIM`, `EVIDENCE`, `DECISION`, `NEGATIVE_RESULT`, `GOVERNANCE`, `AI_CONTRIBUTION` |
| BEGIN/END match | `type` and `ref` on BEGIN and END must be identical |
| Title | optional free text may appear inside body; not a structural delimiter |
| Metadata | lines of form `- key: value` between markers, before body |
| Body separator | either a line `---` after metadata, **or** the first non-empty line that does not start with `- `, then body continues to END |
| Refs | ASM/CLM/EVD/DEC/NEG → `PREFIX-####`; GOVERNANCE → fixed `GOV-0001`; AI_CONTRIBUTION → `AIC-####` |
| Uniqueness | same-type ref unique within a file; different types must not share the same ref string |
| Omission | omitting an optional key = key absent; empty-string values are illegal |
| Unicode / newlines | fixtures use **LF** bytes; equality/compare for content identity after **NFC**; trailing spaces **are significant** inside records for append-only Decision byte comparison |
| Nested headings | `##` inside body must remain inside the same record |

### Required / optional keys and enums

| TYPE | Required keys | Optional keys | Enums |
| --- | --- | --- | --- |
| ASSUMPTION | `status`, `scope`, `rationale`, `falsifiable_when` | `impacts`, `supersedes`, `superseded_by`, `reviewed` | `status`: `ACTIVE` / `SUPERSEDED` / `RETIRED` |
| CLAIM | `status` | `evidence_refs` (comma-separated EVD refs) | `status`: `OPEN` / `SUPPORTED` / `CONTESTED` / `WITHDRAWN` |
| EVIDENCE | `claim_ref`, `polarity`, `kind` | `source_citation`, `source_sha256` | `polarity`: `SUPPORT` / `OPPOSE` / `LIMIT`; `kind`: `QUOTE` / `PARAPHRASE` / `INFERENCE` / `COMPUTATION` |
| DECISION | `date`, `question`, `options`, `choice`, `basis`, `cost`, `reversible`, `revisit_when` | `opposes`, `evidence_refs`, `supersedes` | `reversible`: `true` / `false`; `date`: `YYYY-MM-DD` |
| NEGATIVE_RESULT | `status`, `failed_route`, `failure_evidence_refs`, `impact`, `retry_when` | `related_claims`, `related_decisions` | `status`: `OPEN` / `CLOSED` |
| GOVERNANCE | `project_data_level`, `external_processing_authorized` | `license_status`, `notes` | `project_data_level`: `PUBLIC` / `PERSONAL` / `RESTRICTED`; `external_processing_authorized`: `true` / `false` |
| AI_CONTRIBUTION | `date`, `role`, `summary`, `human_review` | `tools` | `human_review`: `PENDING` / `ACCEPTED` / `REJECTED` |

External Source rule: if `kind` is `QUOTE` or `PARAPHRASE`, at least one of `source_citation` or `source_sha256` is required.

### File placement

| File | Records |
| --- | --- |
| `assumptions.md` | ASSUMPTION |
| `evidence.md` | CLAIM **and** EVIDENCE, separated only by RESEARCH-RECORD markers; CLM has `evidence_refs:`; EVD has `claim_ref:` plus `polarity` / `kind` |
| `decisions.md` | DECISION (append-only) |
| `negative_results.md` | NEGATIVE_RESULT |
| `governance.md` | one GOVERNANCE (`GOV-0001`) plus zero or more AI_CONTRIBUTION |

Point implementers to Spec §3.3 for full legal/illegal examples. Tasks 1–2 **must** include parser grammar tests (markers, nested `##`, metadata/body split, NFC/LF fixtures).

## Candidate operation rules (all write ops)

1. **One record per candidate file** (exactly one BEGIN/END pair).
2. Same `ref` already present and content equal after NFC + LF normalization → `NO_OP`.
3. Same `ref` already present and content different → `REJECTED`, zero official byte change.
4. **No auto-assign ref** unless a future Task explicitly defines **and** tests an allocator; v1.1 default = candidate supplies ref.
5. Candidate path **must not** be the official file path being replaced/appended into.
6. Parse or post-validate failure → official bytes unchanged → `REJECTED`.
7. **AI Contribution:** write via `update_governance` candidate that replaces/appends `AI_CONTRIBUTION` (and/or updates `GOV-0001`) inside `governance.md` under human review authority. **No** separate `append-ai-contribution` CLI in v1.1.

Authorized mutating API surface:

`init_project` · `add_assumption` · `supersede_assumption` · `add_claim` · `add_evidence` · `append_decision` · `record_negative_result` · `update_governance` · `reconcile_project`

CLI write verbs: `init`, `add-assumption`, `supersede-assumption`, `add-claim`, `add-evidence`, `append-decision`, `record-negative-result`, `update-governance`, `reconcile`.

CLI read verbs: `check`, `status`, `doctor`, `check-append-only`, plus `assess-external-processing` (surfaces `ExternalProcessingAssessment`).

## Init / path safety semantics

| Target state | Result |
| --- | --- |
| Absent | full scaffold staged then committed atomically → `WRITTEN` |
| Complete valid scaffold | no overwrite → `NO_OP` |
| Incomplete or conflicting | `REJECTED`, **zero file change** (no silent half-fill) |

Path safety (production CLI):

- resolved path **must** be under repo `07_项目/`;
- reject `_模板` as a project path;
- reject `..` escape;
- reject landing in `01_知识库/` or `11_学习证据/` (or other non-project Source roots);
- Windows / POSIX / paths with spaces must behave identically after resolve;
- tests use a **disposable** repo root (fake tree), never mutate production `07_项目` unless Task 14 is human-authorized.

Scaffold staging: write to a temp staging tree, validate completeness, then atomic move/replace into destination so a crash cannot leave a half-written project.

## Governance vs external processing

- `validate_project` checks structure, grammar, relations, Generated boundaries. It does **NOT** fail solely because `RESTRICTED` or `PERSONAL` + `external_processing_authorized: false`.
- Missing `project_data_level` → `validate_project` **FAIL**.
- `assess_external_processing(project) -> ExternalProcessingAssessment`: `ALLOWED` or `BLOCKED`.
- Restricted/Personal without authorization → assessment `BLOCKED`, but contract validation may still **PASS**.
- Public with recorded license → may be `ALLOWED` for formal external processing of that asset.
- Missing license on an external asset → that asset blocked for formal external processing.
- v1.1 ships **no** real remote upload code path.

def _sha256_tree(root: Path) -> dict[str, str]:
    out = {}
    for path in sorted(root.rglob("*")):
        if path.is_file():
            out[path.relative_to(root).as_posix()] = hashlib.sha256(path.read_bytes()).hexdigest()
    return out

    repo = tmp_path / "repo"
    knowledge = repo / "01_知识库"
    attempts = repo / "11_学习证据"

    attempts.mkdir(parents=True)

    (attempts / "KEEP.md").write_text("unchanged\n", encoding="utf-8", newline="\n")
