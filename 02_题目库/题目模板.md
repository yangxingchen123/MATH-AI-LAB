# Problem Authoring Template v1

对应 **Problem Schema v1 — Frozen**。本文件是 **Safe Authoring Scaffold**，不是 Schema、不是 Validator、不是 Creator、不是真实 Problem 对象。

`id: P0000` 仅用于模板 / Schema 示例（documentation sentinel）。创建真实 Problem 时必须替换为真实 `Pdddd`，**不得实际分配 P0000**。

正式字段、类型、lifecycle 与关系语义只以 `元数据规范.md` 为准。不要从本模板反推 Schema。

默认 YAML 表示新建最小 **draft**。不要默认写入 `knowledge` 或 `parts`。

目录 `未解决/` / `研究中/` / `已解决/` 是工作流组织，**不等于** YAML `status`。

## 可选章节

按需要使用，不要为填空而生成空标题。

- `## 条件与目标`
- `## 思路`
- `## 解答 / 证明`
- `## 验证`
- `## 易错点`
- `## 变式`
- `## 研究说明`

Research / Ordinary 共用 `type: problem`。研究型题目可在正文使用研究背景、候选思路、当前结论等章节，不另建第二套模板。

YAML 管理结构化合同；Markdown 写数学内容。不要把题面、证明、答案或学习结果改成大量 YAML 字段。

---

## 可选：multipart `parts`

仅当题目真实包含多个稳定小问时加入。不要给单题写 `parts: [main]`。

`parts` 是 Problem-local、stable 的 `list[str]`，至少 2 项；不是 child Problem，不是 Attempt result。一旦 Evidence 引用后，不应随意重命名（history-sensitive）。

```yaml
parts:
  - a
  - b
  - c
```

数字型 anchor 必须是 YAML 字符串，不能写成整数：

```yaml
parts:
  - "1"
  - "2"
```

---

## 升级到 reviewed（checklist）

不要维护第二份 reviewed 模板。升级前确认：

- □ Problem identity 已稳定
- □ 数学任务陈述已经审核
- □ Metadata 已审核
- □ knowledge mapping 已完成
- □ multipart 时 parts 已稳定
- □ 如正文已有 proof / solution，其已有内容已审核

差异示例（mapping 已完成且有直接对象）：

```yaml
status: reviewed
knowledge:
  - Kxxxx
```

差异示例（mapping 已审核完成，但当前正式 reviewed Knowledge inventory 没有合适 directly engaged target）：

```yaml
status: reviewed
knowledge: []
```

`reviewed` + `knowledge: []` **不是**「还不知道关联什么」。mapping 未完成时应保持 `draft` 并省略 `knowledge`。

## 不要写入 Problem YAML

Deferred（不属于 v1，不要用注释占位）：`domain`、`source`、`problem_type`、`aliases`、`methods`。

也不要写入动态 / Derived 字段，例如：`result`、`correct`、`incorrect`、`mastery`、`success_rate`、`mistake_count`、`last_attempt`、`last_reviewed`、`review_due`、`personal_difficulty`、`time_spent`、`hint_used`、`confidence`、`intrinsic_difficulty`、`tags`、`attempts`、`error_modes`、`part_result`、`part_score`、`part_correct`、`parent_problem`、`child_problem`、`children`、`subproblem_ids`。

这些字段未来可能属于 Attempt 或 Derived Learning State，只是不属于 Problem Schema v1。

## 创建后验证

1. 基于本模板创建 draft，替换 `P0000`，填写真实标题与日期。
2. 保存到 `02_题目库/`（模板文件本身不是真实 Problem）。
3. 单文件（全库上下文）：

```text
python -m tools.problem_validator check-file "<新 Problem 路径>"
```

4. 批量修改后：

```text
python -m tools.problem_validator check
```

不要使用已 DEPRECATED 的 Candidate Gate 作为正式验证。
